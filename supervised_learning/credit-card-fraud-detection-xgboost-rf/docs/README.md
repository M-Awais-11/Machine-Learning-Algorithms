## 1. Project goal

The goal is to identify **fraudulent transactions** among credit card transactions. This is a **supervised learning** (binary classification) problem, because every transaction in the dataset carries a label:

- `Class = 0`: normal transaction
- `Class = 1`: fraudulent transaction

The main difficulty is that the dataset is **heavily imbalanced**: only 473 of 283,726 transactions are fraud (**0.17%**). Because of this, plain accuracy is a useless metric, so the project uses precision, recall, F1, ROC-AUC and PR-AUC.

## 6. Step-by-step explanation

### 6.1 Setup and helper functions

Two helper functions were created:

- `save_plot(filename)`: saves every graph to `outputs/graphs/` at 150 dpi.
- `save_artifacts(...)`: saves the model, scaler and `config.json` to `outputs/models/`.

Folders are created automatically with `os.makedirs(..., exist_ok=True)`.

### 6.2 Data quality checks

1. `isnull().sum()` was used to check for missing values. None were found.
2. `duplicated().sum()` found **1,081 duplicate rows**.
3. `drop_duplicates()` removed them.

**Why remove duplicates?** If the same transaction appears in both the train and test sets, the model effectively memorizes the test set and the results look better than they really are. This is called **data leakage**.

### 6.3 Class imbalance

There are 283,253 normal transactions and 473 fraud transactions. A model that labels every transaction "normal" still scores **99.83%** accuracy while catching zero fraud. That is why accuracy was not used.

### 6.4 Exploratory Data Analysis (EDA)

#### Amount distribution

- Most transactions in both classes are small amounts.
- Normal transactions go up to 25,000, while the largest fraud is about 2,100.
- The median fraud amount (9.82) is lower than the median normal amount (22.00).
- `Amount` is right-skewed and has outliers, which is why **RobustScaler** was used later.
- The notebook plots this on a **log scale** so that both small and large bars are visible.

#### Time distribution

- Normal transactions follow a day/night cycle.
- Fraud is more uneven (spikes around 10k, 40k and 90k seconds) and also happens when normal activity is low.
- There are only 473 fraud cases, so some spikes may be noise. `Time` alone is not a strong feature.

#### Correlation with the target

- `V17`, `V14`, `V12` and `V10` are the most **negatively** correlated with fraud (V17 is about -0.31).
- `V11` and `V4` are the most **positively** correlated.
- The linear correlation of `Time` and `Amount` is close to zero.
- Correlation only captures **linear** relationships. Tree-based models also learn non-linear patterns, so no feature was dropped based on correlation alone.

### 6.5 Train/test split and scaling

![Stratified split](pics/08_stratified_split.png)

```python
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42
)
```

- **80% train** (226,980 rows), **20% test** (56,746 rows).
- **`stratify=y`**: both sets keep the same fraud ratio (train 0.1665%, test 0.1674%).
- The test set has about **95 fraud cases**, so even a change of 1 or 2 cases moves the metrics noticeably.

**Scaling:**

- Only `Time` and `Amount` were scaled, because `V1` to `V28` are already PCA outputs.
- `RobustScaler` was used. It relies on the median and IQR, so it is less affected by outliers.
- The scaler was **fitted on the train set only** (`fit_transform`), and only `transform` was applied to the test set. Otherwise test information would leak into training.
- **The split was done before scaling and sampling**, which is also essential to avoid leakage.

### 6.6 Handling class imbalance

![Sampling strategies](pics/06_sampling_strategies.png)

Sampling was applied **to the training set only**. The test set was never resampled, so it stays like real-world data.

| Approach | Train set after sampling |
|---|---|
| Original + class weights | Normal 226,602, Fraud 378 (with weights) |
| SMOTE | Normal 226,602, Fraud 226,602 |
| SMOTE + Undersampling | Normal 45,320, Fraud 22,660 (2:1 ratio) |

Class weights were applied only to the original data. The SMOTE datasets are already balanced, and adding weights there would correct the imbalance **twice**.

Note: SMOTE turned 378 real fraud cases into about 226,000, so most fraud samples are **synthetic**. That is why results were always judged on the untouched test set, never on train scores.

### 6.7 Model training

Two algorithms (XGBoost and Random Forest) were trained on three datasets, giving **6 models** in total. All were evaluated on the same test set at the default threshold of 0.5.

**XGBoost parameters:**

| Parameter | Value | Meaning |
|---|---|---|
| `n_estimators` | 200 | 200 trees |
| `max_depth` | 5 | maximum depth of each tree |
| `learning_rate` | 0.1 | contribution of each tree |
| `scale_pos_weight` | ratio (on Original) or 1 | increases the penalty for fraud errors |
| `eval_metric` | `aucpr` | evaluated on PR-AUC |
| `random_state` | 42 | repeatable results |
| `n_jobs` | -1 | use all CPU cores |

`ratio = normal count / fraud count` (about 599 in the training set).

**Random Forest parameters:**

| Parameter | Value |
|---|---|
| `n_estimators` | 100 |
| `class_weight` | `"balanced"` (on Original), otherwise `None` |
| `random_state` | 42 |
| `n_jobs` | -1 |

A model outputs a **probability** (0 to 1). The threshold is the cut-off above which a transaction is called fraud. The default is 0.5, but it is not the best choice for every problem. Details are in [section 10](#10-threshold-selection-and-cost-analysis).

## 7. Algorithms in detail

### 7.1 XGBoost (Extreme Gradient Boosting)

![XGBoost boosting](pics/04_xgboost_boosting.png)

**Type:** Gradient Boosted Decision Trees (ensemble).

**How it works:**

1. A first small decision tree is built and makes rough predictions.
2. Each new tree is then built to fix the **errors** of the previous trees. This happens sequentially (boosting).
3. `learning_rate` controls how much each tree contributes.
4. At the end, the predictions of all trees are added together.
5. The **gradient** of the loss function is used so that the next tree learns in the right direction.
6. Built-in **regularization** limits overfitting.

**Why it was used in this project:**

- It performs very well on tabular data.
- `scale_pos_weight` handles the imbalance directly.
- It captures non-linear patterns.
- **Result:** best PR-AUC (0.8204), on the Original data.

### 7.2 Random Forest

![Random Forest](pics/03_random_forest.png)

**Type:** Bagging ensemble of decision trees.

**How it works:**

1. Several random samples (**bootstrap**) are drawn from the training data.
2. A decision tree is built on each sample, and each split looks at only a random subset of features.
3. All trees are built **in parallel**, independently of each other.
4. The final prediction is the **vote/average** of all trees.

**Difference from boosting:** In Random Forest the trees are independent and reduce variance. In XGBoost each tree corrects the mistakes of the previous ones.

**For imbalance:** `class_weight="balanced"` gives the fraud class a higher weight.

![Class weights](pics/13_class_weights.png)

### 7.3 SMOTE (Synthetic Minority Over-sampling Technique)

![SMOTE](pics/05_smote.png)

**Purpose:** Create new **synthetic** samples of the minority class (fraud) to balance the classes.

**How it works:**

1. Pick one fraud sample.
2. Find its `k` nearest fraud neighbours (default k=5).
3. Pick one neighbour at random.
4. Create a new sample at a random point on the line between the two:

   `new = sample + random(0,1) × (neighbour − sample)`

**Advantage:** Better than simply copying existing samples (random oversampling), because it creates new points.

**Drawback:** Synthetic data is not real. In this project SMOTE sharply reduced precision (for XGBoost from 0.88 to 0.55).

### 7.4 SMOTE + Random Undersampling (combined)

Two steps in an `imblearn.pipeline.Pipeline`:

1. `SMOTE(sampling_strategy=0.1)`: raises fraud to 10% of the normal count.
2. `RandomUnderSampler(sampling_strategy=0.5)`: randomly removes normal samples so that fraud becomes 50% of normal (a 2:1 ratio).

**Idea:** Not too much synthetic data and not too much real data thrown away. The final train set is smaller (67,980 rows) and less imbalanced.

### 7.5 RandomUnderSampler

It randomly removes samples from the majority class (normal) to improve the class ratio. It is fast, but information from the real data is lost.

### 7.6 RobustScaler

![RobustScaler](pics/07_robust_scaler.png)

Formula:

`scaled = (x − median) / IQR`

where IQR = Q3 − Q1. The median and IQR are not much affected by outliers, so this works better than StandardScaler for a skewed feature like `Amount`.

### 7.7 Decision Tree (building block)

![Decision tree](pics/02_decision_tree.png)

XGBoost and Random Forest are both built from decision trees. A tree splits the data into branches by asking questions (such as "V14 < -2.5?") and finally predicts a class or value. The quality of a split is measured by Gini impurity (Random Forest) or by gradient/loss-based gain (XGBoost).

### 7.8 PCA (already applied to the data)

![PCA](pics/11_pca_concept.png)

`V1` to `V28` are not the original features. They are components from **Principal Component Analysis**. PCA converts correlated features into new uncorrelated ones. The dataset authors did this for privacy. PCA was not run again in this project.

### 7.9 Stratified Train/Test Split

Splitting the data so that both parts keep the same class ratio as the original. With imbalanced data this is essential, otherwise the test set might contain no fraud at all.

### 7.10 Pearson Correlation

`data_frame.corr()` measures the linear relationship (-1 to +1) between each feature and the target. It was used in EDA to understand the features.

## 8. Evaluation metrics

![Confusion matrix and metrics](pics/09_confusion_matrix_metrics.png)

The four parts of a confusion matrix:

| | Predicted Normal | Predicted Fraud |
|---|---|---|
| **Actual Normal** | TN (correct) | FP (false alarm) |
| **Actual Fraud** | FN (missed fraud) | TP (fraud caught) |

| Metric | Formula | Meaning |
|---|---|---|
| **Precision** | TP / (TP + FP) | Of everything flagged as fraud, how much really was fraud |
| **Recall** | TP / (TP + FN) | Of all real fraud, how much was caught |
| **F1** | 2 × (P × R) / (P + R) | Balance of precision and recall |
| **ROC-AUC** | Area under the ROC curve | Ability to separate the classes (optimistic on imbalanced data) |
| **PR-AUC** | Area under the Precision-Recall curve | More trustworthy metric for imbalanced data |

**PR-AUC was the main guide in this project**, because ROC-AUC looks very good for every model on imbalanced data.

(The numbers in the diagram above are from the final model, see section 11.)

## 9. Results and comparison

At the default threshold of 0.5, on the test set:

| Sampling | Model | Precision | Recall | F1 | ROC-AUC | PR-AUC |
|---|---|---|---|---|---|---|
| **Original** | **XGBoost** | 0.8824 | 0.7895 | 0.8333 | 0.9692 | **0.8204** |
| SMOTE | XGBoost | 0.5532 | 0.8211 | 0.6610 | 0.9653 | 0.8142 |
| SMOTE | RandomForest | 0.9136 | 0.7789 | 0.8409 | 0.9590 | 0.8073 |
| SMOTE+Under | XGBoost | 0.5390 | 0.8000 | 0.6441 | 0.9700 | 0.8063 |
| SMOTE+Under | RandomForest | 0.7857 | 0.8105 | 0.7979 | 0.9710 | 0.8020 |
| Original | RandomForest | 0.9710 | 0.7053 | 0.8171 | 0.9246 | 0.7960 |

**Findings:**

- PR-AUC values are close (0.796 to 0.820). The test set has only about 95 fraud cases, so the differences may partly be noise and there is no clear winner.
- SMOTE raised XGBoost recall slightly (0.79 to 0.82) but precision dropped sharply (0.88 to 0.55), meaning far more false alarms.
- **Original + XGBoost** has the best PR-AUC and a good precision/recall balance, without any resampling. That is why it was chosen as the final model.
- Random Forest (Original) has the highest precision (0.97) but the lowest recall (0.71), so it misses the most fraud.

## 10. Threshold selection and cost analysis

### Precision-Recall trade-off

![Threshold trade-off](pics/10_threshold_tradeoff.png)

- While recall stays up to about 0.80, precision remains between 0.9 and 1.0.
- Beyond 0.80 recall, precision drops quickly: trying to catch more than 80% of fraud produces many false alarms.

### Precision and recall vs threshold

- Between thresholds 0.1 and 0.6, recall stays near 0.80 while precision rises from about 0.65 to 0.90. In this range, raising the threshold safely improves precision.
- Below 0.1, precision falls very fast in exchange for only a tiny gain in recall.
- Above 0.9, recall starts to fall.
- The curves look like steps because the test set has only about 95 fraud cases, so the threshold should be reported as a **range**, not one exact value.

### Business cost model

![Cost model](pics/12_cost_model.png)

```
Total Cost = (FP × COST_FP) + (FN × COST_FN)
```

Assumptions (for illustration; a real bank should replace them with its own figures):

- `COST_FN = 500`: loss from one missed fraud
- `COST_FP = 10`: cost of one false alarm (review, customer support)

Results at different thresholds:

| Threshold | Precision | Recall | FP | FN | Total Cost |
|---|---|---|---|---|---|
| 0.05 | 0.5270 | 0.8211 | 70 | 17 | **9,200** |
| 0.10 | 0.6581 | 0.8105 | 40 | 18 | 9,400 |
| 0.30 | 0.8172 | 0.8000 | 17 | 19 | 9,670 |
| **0.40** | **0.8444** | **0.8000** | **14** | **19** | **9,640** |
| 0.50 | 0.8824 | 0.7895 | 10 | 20 | 10,100 |
| 0.60 | 0.9024 | 0.7789 | 8 | 21 | 10,580 |
| 0.80 | 0.9351 | 0.7579 | 5 | 23 | 11,550 |
| 0.90 | 0.9730 | 0.7579 | 2 | 23 | 11,520 |
| 0.95 | 0.9722 | 0.7368 | 2 | 25 | 12,520 |

(The full table is in `outputs/threshold_analysis.csv`.)

### Choosing a strategy

| Strategy | Threshold | Precision | Recall | FP | FN | When to use |
|---|---|---|---|---|---|---|
| Maximum fraud catch | 0.05 | 0.53 | 0.82 | 70 | 17 | Fraud losses are very large and the review team is big |
| **Balanced (chosen)** | **0.40** | **0.84** | **0.80** | **14** | **19** | Near-minimum cost, 5x fewer false alarms |
| Minimal customer annoyance | 0.85 to 0.90 | 0.96 to 0.97 | 0.76 | 2 to 3 | 23 | Customer experience matters most |

**Decision:** Threshold **0.40** (reasonable range 0.3 to 0.5). The cost difference between 0.05 and 0.40 is about one missed fraud (9,200 vs 9,640), which is within the noise of this small test set. Moving from 0.40 to 0.05 catches only 2 more fraud cases but adds 56 extra false alarms.

**Caveat:** The threshold was chosen on the test set, so the numbers are slightly optimistic. In production the threshold should be chosen on a separate **validation set**, and the test set kept for a final check only.

### Predicting one transaction

The `predict_fraud(transaction)` function:

1. Takes one transaction (raw values).
2. Scales `Time` and `Amount` with the saved scaler.
3. Gets the fraud probability from the model.
4. Returns `"FRAUD"` if the probability is >= the threshold, otherwise `"NOT FRAUD"`.

In the demo, one real fraud (probability 0.9975, FRAUD) and one normal transaction (probability 0.0, NOT FRAUD) were predicted correctly.

### Verification

In the notebook, the saved files were reloaded with `joblib.load` and `config.json`, and the same predictions were run. The results were identical, which shows that the saved model works on its own (without the training objects).

## 13. Limitations

- The test set has only about 95 fraud cases, so small differences between models and thresholds cannot be fully trusted.
- The cost values (500 and 10) are assumptions.
- The threshold was chosen on the test set. Production needs a separate validation set.
- The data covers only two days of transactions, and fraud patterns change over time. The model needs regular retraining and monitoring.
- SMOTE's synthetic samples do not fully represent real fraud patterns.

---

## 14. Conclusion

- **Problem:** Fraud is only 0.17%, so accuracy is useless and the work focused on precision, recall and PR-AUC.
- **What worked:** XGBoost on the original data (with `scale_pos_weight`) gave the best PR-AUC (0.820). SMOTE and SMOTE + undersampling did not improve results on this dataset and mainly lowered precision.
- **Precision vs recall:** Lowering the threshold catches more fraud but also raises false alarms. At 0.05 recall is 82% and precision 53%, while at 0.40 recall is 80% and precision 84%.
- **Business decision:** A threshold of about **0.40** (range 0.3 to 0.5) is recommended. The real threshold depends on the bank's actual fraud losses and the cost of false alarms.

## 15. Glossary

| Term | Meaning |
|---|---|
| Supervised learning | Learning from data that already has labels |
| Imbalanced data | Data in which one class is very rare |
| Data leakage | Test information reaching the training process |
| Overfitting | A model memorizing the training data and failing on new data |
| Ensemble | Combining several models into one |
| Boosting | Building models one after another, each fixing the previous errors |
| Bagging | Building models independently on different samples and averaging them |
| Threshold | The probability cut-off above which a transaction is called fraud |
| PCA | A way to convert features into new uncorrelated components |
| Stratified | Keeping the class ratio the same in every part |
| Hyperparameter | A setting chosen by us before training (such as `max_depth`) |
| Synthetic sample | A new sample created by an algorithm, not a real one |
